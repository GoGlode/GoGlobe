## После выдачи API

1. Проверить базовый URL и песочницу, выдачу/отзыв ключей и правила авторизации.
2. Проверить хотя бы один реальный запрос: цены, наличие, даты и состав гостей/пассажиров.
3. Уточнить квоты, таймауты, повторяемые ошибки, правила кэша и лицензии фото.
4. Написать конкретные реализации двух Provider-интерфейсов. Нормализовать ответ в схемы HotelOffer/FlightOffer/Source/Price v0.3.
5. Проверить валюту и единицы (целые копейки), покрытие суммы, налоги, обе стороны перелёта, даты проживания и ссылочную целостность source_ids.
6. Подключить реализации к инструментам агента, ограничить каждый вызов общим deadline. Сравнить контрольные ответы и ошибки с mock-режимом.

Вставки одного API-ключа будет достаточно только после написания конкретного адаптера. Без документации нельзя заранее угадать endpoint, авторизацию и поля JSON. Клиентский контракт BFF при этом уже определён и не должен зависеть от поставщика.

Секреты находятся только на сервере. Здесь нет вымышленных URL или ключей. Отсутствующие тарифы не становятся нулевыми или подтверждёнными.
