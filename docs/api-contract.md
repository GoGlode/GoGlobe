# API-контракт v0

Источник правды: `backend/app/schemas/search.py` (Pydantic). Зеркало: `frontend/src/api/types.ts`. Владелец: Backend №1.
Живая схема: `GET /openapi.json`, Swagger — `/docs`.

## POST /api/search
Запрос:
```json
{ "query": "5 дней в Турцию в ноябре, на двоих, до 120 000 ₽, отель у моря, прямой рейс",
  "params": { "dates": {"from":"2026-11-10","to":"2026-11-15"}, "budget": {"amount":120000,"currency":"RUB"},
              "travelers": 2, "wishes": ["sea_view","direct_flight"] },
  "search_id": "опционально, генерирует клиент" }
```
Ответ: `{ search_id, status, parsed, clarifying_question, offers[], warnings[] }`.

### Валидация входа (HTTP 422)
| Поле | Правило | Пример нарушения |
|---|---|---|
| `query` | 1…2000 символов | пустая строка или «простыня» на 10 000 символов |
| `params.travelers` | `>= 1` | `0`, `-2` |
| `params.dates.from` / `to` | ISO `YYYY-MM-DD`, существующая календарная дата | `2026-02-30`, `10.11.2026` |
| `params.dates` | `from <= to` | `2026-11-10` → `2026-11-05` |

Ошибки в **тексте** запроса (например, «с 31 по 32 ноября») — не 422, а `needs_clarification` + причина в `warnings`.

### Валюты
`parsed.budget` остаётся в валюте пользователя. При проверке бюджета сумма пересчитывается в валюту цен провайдера по демо-курсу (`app/agent/currency.py`), факт пересчёта пишется в `warnings`. Курсы — константы демо, не биржевые данные.

| status | Когда | UI |
|---|---|---|
| `ok` | есть варианты, предупреждений нет | карточки |
| `needs_clarification` | не хватает параметра | показать `clarifying_question` |
| `partial` | есть варианты, но часть данных/источников недоступна | карточки + `warnings` |
| `empty` | ничего не подошло | честное «пусто» + совет изменить параметры |
| `error` | сбой | ошибка + повтор (внутренние детали — только в лог сервера) |

> Справка о сезонности и температуре **не** считается деградацией: она уходит в `explanation.pros`,
> а не в `warnings`. Поэтому успешный поиск достижимо получает `ok`.

## GET /api/search/{id}/events (SSE)
`data: {"stage":"parsing|flights|hotels|validating|ranking|done|error","message":"…"}`

- Одна стадия — одно событие: сообщения берутся из плана агента (`build_search_plan`), дублей «план + выполнение» нет.
- Новый POST с тем же `search_id` сбрасывает события прошлого прогона.
- Если событий нет `GOGLOBE_SSE_IDLE_TIMEOUT` секунд (по умолчанию 15), поток отдаёт `error` и закрывается — не висит.
